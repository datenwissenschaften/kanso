# Architecture and contracts

- Organize by feature and cohesive responsibility. Use descriptive names, shallow control flow, guard clauses and early returns. Avoid generic helpers, speculative abstractions and pass-through wrappers. Prefer pure functions and immutable data where practical.
- Keep handwritten classes at most 100 physical lines including declarations and comments. Split by responsibility. Exclude generated classes and report unavoidable framework constraints.
- Type interfaces, inputs, outputs and public attributes where supported. Use strict static checks. Require explicit arguments in new owned application APIs. Preserve existing contracts and honor signatures mandated by frameworks or third-party APIs.
- Define states, units, invariants, and failure behavior explicitly. Reject missing configuration at startup. Load and validate it once at the composition root and inject dependencies. Use named constants or declarative settings for meaningful values. Avoid silent coercion, fallback, reflection, implicit registration and hidden global state.
- Keep package and module initialization free of application logic and side effects except required framework entry points. Avoid wildcard imports and unnecessary local imports. Use structured application logging through the project's logger or standard facilities.
- Document rationale, public contracts, legal notices and required annotations where useful. Remove obsolete commented-out code and preserve useful documentation.
- Prefer composition and explicit dependency injection. Consider Strategy for interchangeable behavior, Adapter for integration boundaries, State for transitions, and Factory for complex construction. Facade, Repository, Decorator, Command, Pipeline, and Ports and Adapters are options when they simplify a concrete boundary. Isolate domain logic from infrastructure when it improves testability.
- Preserve supported APIs, formats and persisted data by default. For an authorized breaking major release, migrate internal callers and reject unsupported formats explicitly. Add compatibility paths only when required. Obtain separate authorization for destructive migration steps.
